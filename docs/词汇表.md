# 词汇表（通用语言）

访谈中沉淀的领域术语，代码、文档、简历统一用词。

## 限界上下文

| 上下文 | 管什么 | 主要载体 |
|---|---|---|
| 部署编排 | SOP、工具链、提示词 | `tools/`、`SKILL.md`、`prompts.py` |
| 审批治理 | 人工审批、中断/恢复、决策 | `DeployApprovalMiddleware` |
| 风险控制 | 并发锁、危险操作前置校验 | `RiskControlMiddleware` |
| 审计追踪 | 工具调用审计、五种状态 | `audit.py`、`AuditLogMiddleware` |
| 部署状态 | 部署记录、状态机、回滚关联 | `state.py`、`DeploymentStateMiddleware` |
| 会话记忆 | 线程、检查点、历史恢复 | `api.py` 线程接口、`checkpoints.db` |

## 核心术语

| 术语 | 含义 |
|---|---|
| SOP | 标准部署流程：拉代码 → 构建 → 审批 → 停 → 删 → 起 → 健康检查 |
| thread_id | 一次对话/部署任务的唯一标识，审计与状态的关联键 |
| action_requests / review_configs | 审批中断载荷：待审批动作 + 每条动作允许的决策 |
| decisions | 人工决策：`approve` / `reject`（`edit` 暂按 reject 处理） |
| 风险等级 | low（只读巡检）/ medium（文件·白名单变更）/ high（容器启停删·回滚） |
| 审计状态 | ok / failed（工具失败）/ blocked（风险控制拒绝）/ rejected（审批拒绝）/ error（执行异常） |
| 部署状态 | pending / building / deploying / healthy / unhealthy / failed / rolled_back |
| 白名单 | 三类：容器名（CONTAINER_NAMES）、镜像前缀（IMAGE_PREFIX）、工作区（WORKSPACES） |
| 场景 scenario | 一条 Evals 用例：用户需求 + 服务器初始状态 + 期望检查 |
| 断言 assertion | 确定性检查，如顺序、审批触发、参数合法性 |
| golden 集 | 手工编写的标准场景集，用作 PR 门禁 |
| 回放 replay | 用生产审计/状态记录重放真实历史，用作回归池 |
| 门禁 gate | PR 合并前必须通过的检查 |
| 裁判 judge | LLM-as-judge：用模型评价规则写不出的质量维度 |
| 红线 | 必须满分的指标，一次不过拦合并（审批召回、SOP 顺序） |
| 分层 | PR 跑快集拦合并，nightly 跑重型全量 |
| 沙箱 sandbox | 本地真 docker 环境跑 Evals，又真又重，只放 nightly |
| SubAgent | 4 个：code-agent / build-agent / deploy-planner / monitor-agent，经 task 委派 |
| 工具主责 | 每个工具的归属 SubAgent；只读可共享，高风险写独占主 Agent |
| 高风险上收 | 审批名单内写操作只由主 Agent 亲调，复用主层审批审计链路 |
| 三过成功 | 容器 running + HTTP 200 + 日志无 ERROR 全过才算部署成功 |
| 冒烟 smoke | 3-5 条核心场景的最小集合 |
| 基线 baseline | 优化前的指标快照，前后对比的起点 |
