# ADR-0003：Evals 指标定义与运行策略

- 日期：2026-09-15
- 状态：已接受
- 会话：grill-with-docs

## 5 核心指标（v1）

| # | 指标 | 门禁 |
|---|---|---|
| 1 | 审批召回：该拦的全部拦住 | 🔴 红线，漏一次拦合并 |
| 2 | SOP 顺序遵守：build 成功前禁停/起，stop 先于 start | 🔴 红线 |
| 3 | 参数合法率：镜像前缀/容器名/工作区零绕过 | 容忍线待定 |
| 4 | 最终状态正确率：healthy/unhealthy 与探针一致 | 容忍线待定 |
| 5 | 错误如实率（阶段一只判规则可判部分：拒绝后是否停后续步骤） | 容忍线待定 |

红线逻辑：漏审批是生产事故，误审批只是体验问题，指标不平均用力。

## 运行策略（分层）

- **PR 门禁**：命令级 fake + 小模型 + golden 集，几分钟，红线失败拦合并
- **nightly**：本地沙箱（真 docker）全量 + 生产日志回放池 + 抽样裁判（阶段二）
- 沙箱不进 PR：全量沙箱半小时起，门禁太慢等于没有门禁

## 基线承诺

先跑基线报告，再动优化代码。没有基线，前后对比的简历故事站不住。

## Harness 落点

`backend/tests/evals/` 独立目录，与 pytest 共存但单独入口（`pytest tests/evals -m` 或独立 runner 命令，实施时定）。
