# Spec：M1 Evals 评估体系（阶段一：规则断言先行）

- status: ready-for-agent
- 依据：ADR-0001（路线目标）、ADR-0002（阶段一方案）、ADR-0003（指标与运行策略）
- 术语：`docs/词汇表.md`（场景、断言、golden 集、回放、门禁、红线、分层、沙箱、基线）

## Problem Statement

用户（部署 Agent 的开发者）每次改提示词、工具逻辑或模型，Agent 有没有变坏只能靠肉眼点一遍验证。部署顺序错乱、审批漏触发、参数绕过白名单这类事故，只能在生产环境被发现。没有量化基线，任何优化都无法证明有效。

## Solution

一套 Evals 门禁：手工 golden 场景集 + 全确定性断言，真调小模型，PR 自动跑，红线失败拦合并；nightly 跑沙箱全量 + 生产日志回放；先产出基线报告，再谈优化。阶段一只做规则断言，不引入外部评测框架和 LLM 裁判。

## User Stories

1. 作为开发者，我想要一条命令跑完全部 golden 场景并看到 5 指标通过率，以便改完 prompt 当天就知道有没有 regression。
2. 作为开发者，我想要审批召回断言（该拦的工具调用必须触发审批中断），以便审批名单改坏时 PR 直接变红。
3. 作为开发者，我想要 SOP 顺序断言（build 成功前禁停/删/起，停先于删先于起），以便顺序约束被破坏时立刻发现。
4. 作为开发者，我想要参数合法断言（镜像前缀、容器名、工作区零绕过），以便白名单校验被绕过时立刻发现。
5. 作为开发者，我想要最终状态断言（healthy/unhealthy 与探针一致），以便 Agent 谎报成功时被抓住。
6. 作为开发者，我想要拒绝后停手断言（reject 后不再调后续高风险工具），以便错误恢复语义被破坏时被发现。
7. 作为开发者，我想要 approve 场景下工具链跑通不断言误杀，以便正常部署流程不受门禁干扰。
8. 作为开发者，我想要 reject 场景下审计留痕可查，以便审批链路可追溯。
9. 作为开发者，我想要回滚场景覆盖（部署失败走回滚工具），以便回滚链路有回归保护。
10. 作为开发者，我想要 SSH 失败场景覆盖（命令失败/连接异常），以便重试一次与如实上报语义被保护。
11. 作为开发者，我想要幻觉防护场景（编造工具名、编造参数），以便模型胡编时被发现。
12. 作为发布负责人，我想要 PR 门禁几分钟跑完且红线失败拦合并，以便红线是有牙齿的。
13. 作为开发者，我想要新增 golden 场景只需加一条数据而不改 harness，以便场景池随生产事故持续生长。
14. 作为开发者，我想要 nightly 全量在沙箱真环境跑，以便 mock 掩盖的真问题能被发现。
15. 作为开发者，我想要生产审计与状态记录能转成回放用例，以便真实事故沉淀为回归池。
16. 作为开发者，我想要基线报告落盘（含 5 指标 × 场景矩阵），以便优化前后对比有据可依。
17. 作为开发者，我想要 Evals 与现有单元测试同一套命令体系但独立入口，以便快集与慢集互不拖累。

## Implementation Decisions

- 新模块：evals harness（含场景定义、运行器、断言库），置于现有后端测试体系内，与现有测试运行器共存但单独入口。
- 测试 seam（唯一）：端到端跑 Agent —— SSH 命令层 mock（沿用现有工具测试的 mock 传统），审批中断 mock（沿用现有审批测试模式），断言审计记录 + SSE 事件 + 部署状态。不新增低层 seam。
- 5 指标全部确定性断言；红线两项（审批召回、SOP 顺序）阈值 100%，其余三项容忍线实施时定。
- 数据集：手工 golden 集（PR 门禁，约 10 条）用与现有测试一致的数据定义风格；生产日志回放池（nightly）从审计与部署状态记录转换。
- 运行分层：PR 快集（命令级 fake + 小模型）/ nightly（沙箱 + 回放 + 全量 + 主力抽样）；用测试标记区分快慢集并注册到测试配置。
- 被测模型：小模型全量；nightly 抽样主力模型。
- 基线优先：先跑基线报告再动优化代码；报告落盘位置实施时定。
- 阶段一零外部依赖：不引入 DeepEval / Promptfoo / LangSmith（选型结论：裁判抽样放阶段二，红队按需，LangSmith 因 hosted 成本与敏感数据外发不用）。
- Agent 运行温度已为 0，红线测试天然确定；flaky 处理（重试/隔离）实施时定。

## Testing Decisions

- 好测试只断言外部行为：工具调用序列、审批中断事件、审计行、最终部署状态；不断言 LLM 原文措辞。
- mock 边界只在 SSH 命令层与审批中断点；不断言 mock 自身行为（避免测了个寂寞）。
- 先验：现有工具测试的 SSH mock 模式、审批测试的中断 mock 模式、审计测试的临时库隔离模式。
- 被测模块：evals harness 自身（场景加载、断言语义）+ 端到端场景集。

## Out of Scope

- LLM-as-judge 裁判（阶段二）
- Promptfoo 红队 / 多模型矩阵（按需）
- 沙箱进 PR（只放 nightly）
- 前端 Evals 展示页
- 生产流量实时评估
- 死配置清理、文档过期等非 Evals 技术债
